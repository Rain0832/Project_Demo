# 🧱 Level 10：最小持久化 —— 用文件把数据“活下来”

> **目标一句话**
> 👉 服务重启后，`users` 不再丢失

我们**只用标准库**，不碰数据库，不引入复杂概念。

---

## 一、先看问题本质（非常重要）

### 你现在的程序，本质是：

```text
内存里的一个 slice
```

```go
var users []User
```

* 程序一退出 → 内存释放
* 所有数据 → 直接消失

📌 **问题不是 Go 的问题，是“内存天然不持久”**

---

## 二、最朴素的解决方案（人话版）

> **把内存里的数据，抄一份到硬盘**

* 硬盘：文件
* 格式：JSON（你已经会了）
* 角色：文件 = 简易数据库

---

## 三、Level 10 的整体结构图（心里一定要有）

```text
程序启动
   ↓
尝试读取 users.json
   ↓
如果存在 → json.Unmarshal → users
如果不存在 → 用默认 users
   ↓
HTTP 服务启动
   ↓
POST /users
   ↓
修改 users
   ↓
把 users 写回 users.json
```

---

## 四、你需要掌握的文件 API（只 2 个）

### 1️⃣ 读文件

```go
os.ReadFile("users.json")
```

* 返回：`[]byte`
* 失败常见原因：文件不存在

---

### 2️⃣ 写文件

```go
os.WriteFile("users.json", data, 0644)
```

* 会覆盖原文件
* 文件不存在会自动创建

📌 **这两个函数已经把 90% 文件细节帮你封装好了**

---

## 五、启动时加载数据（一步一步理解）

### 你要做的事

> **启动时：从文件恢复 users**

---

### 逻辑分解（不要急着写）

1. 尝试读文件
2. 如果失败：

   * 说明是第一次启动
   * 用默认 users
3. 如果成功：

   * `json.Unmarshal`
   * 填充 `users`

---

### 心里伪代码（不是让你照抄）

```go
data, err := os.ReadFile("users.json")
if err == nil {
    json.Unmarshal(data, &users)
}
```

📌 注意：

* 失败 ≠ 程序错误
* 很可能只是「文件不存在」

---

## 六、什么时候写文件？（非常关键）

### ❌ 错误想法

* 每次 GET 都写文件
* 每次请求都写文件

🚫 浪费 IO

---

### ✅ 正确时机

> **只有在数据发生变化时写**

在你现在的程序里：

```text
只有 POST /users 会改数据
```

---

### 所以逻辑是：

```go
POST:
  1. 加锁
  2. append users
  3. json.Marshal(users)
  4. 写入 users.json
  5. 解锁
```

📌 文件写入 **必须在锁内**
因为文件内容 = users 的快照

---

## 七、锁 + 文件，一起用会发生什么？

你现在已经有：

```go
var mu sync.Mutex
```

### 你锁保护的对象升级了

以前：

```text
只保护 users slice
```

现在：

```text
保护 users + users.json
```

📌 **它们是一组一致性数据**

---

## 八、为什么这种方案“够用但不专业”？

你现在用的是：

```text
JSON 文件 + 全量写入
```

### 它的问题（你现在只要知道名字）

1. 写文件慢
2. 并发多时 IO 成瓶颈
3. 崩溃可能导致文件损坏
4. 无事务、无回滚

---

### 但它的优点是：

* 极度简单
* 100% 可控
* 非常适合学习阶段

📌 **你现在不是在做生产系统，而是在学后端骨架**

---

## 九、Level 10 的「完成标准」

你做到以下 3 点，就算 **完美过关**：

1. 服务重启后，`GET /users` 数据还在
2. POST 新用户后，文件内容同步更新
3. 没有并发数据竞争（锁用对）
